# 情懷收藏、額外模式及部署

累積成績與可用虛擬獎金分開。全部數字是遊戲分數，不能兌換現金；不用付款或信用卡。

## 公平性

- 原有純每日挑戰、每日榜、賽季榜、生涯總榜，仍只計原有三個免費錦囊的每日成績。
- 可用餘額 = 純每日累積獎金 + 額外模式獎金 − 已消費金額。消費不改寫純每日累積成績。
- 80,000換題券須在開局前買。使用「每日換題挑戰」會消耗今日一次機會和一張券；即使未使用換題亦不退券。這一局只上🛒換題榜，不能同日再開純每日挑戰。
- 換題只能一次，不能在本題已使用錦囊後換；沿用原本倒數。替代題為同難度、不同題目。
- 房間與週末練習不進純每日或換題榜，不增加純每日稱號、知識解鎖或生涯總獎金。完成的個人額外挑戰可在歷史成績重溫。
- 已匿名開始的每日局，不會因登入或改選換題模式得到第二次機會。跨帳戶的每日限制仍以各帳戶和本瀏覽器的確認標記處理。

## 文化與造型

普通抽卡5,000，金蛋50,000保證閃卡。共有18款原創漫畫文化卡，交通、非遺、小吃三系列，各四款普通、兩款閃卡。重複卡保存數量；集齊整個系列可使用稱號前綴。故事附中文參考來源。白牌車卡交代非法取酬載客的法律背景；不把所有交通史物件當成合法現役服務。

抽卡採可重現的收藏序號（伺服器建立時間與抽卡次數），普通卡序列中6/126為閃卡。這是可預測的遊戲偽隨機序列，不是秘密或真金錢抽獎。重新連線不重新抽取。同一筆操作有唯一收據，可核對而不重複扣款。購物後不自動套用，玩家可自行選擇造型；使用設定跨裝置保存。

框：紅白藍20,000、霓虹100,000、金支票500,000。主題：冰室80,000、原創街頭墨字250,000。紅Van割禾青動畫50,000。音效與合成語音預設關閉，可在商店開啟；語音視裝置支援。減少動態效果設定會停用彩紙、光暈及行車移動。

排行榜展示已套用頭像框及系列前綴。分享圖只包含公開稱呼、成績及造型，不含帳戶電郵、題目或答案。

## 週末狂熱

通行100,000，對應香港時間星期六及星期日。平日購買對應即將到來的週末；星期日購買仍於當日有效，介面應留意通行週末日期。可無限重玩隨機15題，每場按答對數×500計額外獎金，最多5,000；每日上限100,000，達上限仍可繼續練習。過香港午夜會結束上一日的挑戰。

## 圍威喂私人房間

- 開房費30,000；房主另提供0–500,000獎金池。其他人免費加入，最多6人。
- 題目可選香港綜合、體育、地理景點。邀請連結有隨機128位元房間代號；持有連結並登入的玩家可查看房間公開稱呼、參加者和分數。私人逐題答案只有本人可讀。
- 兩人起由房主開始，10題共用伺服器時間，每題20秒，3秒揭曉；23秒後同步下一題。離開／斷線不暫停，重連補記超時。
- 260秒後可由參加者核對全場結果（230秒題程＋30秒重連寬限）。只比較已交卷成績：答對多者先，其次時間少者，再其次加入先後。勝出者按「領取」入帳一次。
- 未交卷者在結算時不參與排名；之後可處理進度清除個人活動標記，不能改寫已定結果。
- 房主可取消等候中的房間，退回獎金池、不退開房費。無人交卷時結算為取消，房主可領回池。等候室一小時後停止加入。
- 一名玩家只可有一場未完成額外挑戰。可在遊樂場繼續；房主可在「我建立的房間」找回房間與未領取獎金。

## Firebase（原有獨立 sky-playground-millionaire）

使用 Spark 計劃，沒有新增 Cloud Functions。從本遊戲資料夾執行：

    npm ci
    npx firebase-tools login
    npx firebase-tools deploy --project sky-playground-millionaire --only firestore:rules,firestore:indexes

或在 Firebase Console 發布本資料夾 firestore.rules，並建立 firestore.indexes.json 的索引。完整規則由 scripts/generate-rules.mjs 和 reward-rules.mjs 生成，勿只貼局部片段。

原有3個索引保留，新增2個：
1. hkm_assisted_results：day升、prize降、timeMs升、lifelinesLeft降、completedAt升。
2. hkm_rooms：hostUid升、createdAt降。

新集合：hkm_wallets（含私人不可更改收據）、hkm_styles（公開造型）、hkm_assisted_results（公開換題榜）、hkm_rooms（房間及本人私人sessions）。額外單人進度位於hkm_players/{uid}/sessions。維持原有hkm_命名，不搬遷舊版本。

先部署規則及索引，等索引為Enabled，再上傳已建置網站。只更新網站而未發布規則時，商店或額外模式會permission-denied，原有本機進度仍保留。

## 驗證與限制

單元測試檢查分帳、卡片保底、通行日期、題目唯一性、換題時間、題程及勝負排序。Firestore Emulator直接執行正式SDK交易服務，驗證收據、禁止偽造、完整換題局及房間託管。瀏覽器測試檢查窄屏歷史成績、商店重試、造型、換題局、慶祝及房間操作。

沒有在正式Firebase專案寫測試資料，也沒有代替管理員發布正式規則。真實Google登入仍依賴Authentication已啟用Google及網站授權網域。

Spark純前端架構的題庫與答案可由技術使用者檢視，不能保證抵抗自動答題或多帳戶。規則負責限制金額、次數、伺服器時間、交易一致性及排名隔離；前端禁止複製僅是使用者介面阻擋。若要強抗作弊，需另加可信後端裁判，這次沒有引入付費服務。
