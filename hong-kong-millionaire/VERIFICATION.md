# 驗證範圍

本版於 2026 年 11 月 16 日（香港時間）完成全新進度 v4 與第一題權限修復。

## 第一題根因及真正規則測試

[舊規則的模擬器重現](https://github.com/skyyip/games/actions/runs/43735216425) 在提交第一個正確答案時回報超出 Firestore 每次請求的 **1,000 expressions** 限制。這是規則運算失敗，不能單憑 Google 登入成功、版本字串存在或 SDK 替身測試通過來排除。

[新版真實 Firestore Emulator 測試](https://github.com/skyyip/games/actions/runs/43736446629) 全部通過：**93 項檢查**，使用 Java 21、Firestore Emulator 1.22.0 與 Firebase JS SDK，實際編譯並執行本資料夾完整規則。測試提交與正式程式共用的 `transitionPatch`，而非另造一份答案 payload。

已驗證：

- 私人玩家建立、原子每日開局、第一題及完整 15 題正確作答。
- 三個一次性錦囊、下一題、完整五文件原子結算及 $1,000,000 累積獎金。
- 第一題答錯、主動退出及超時的逐題狀態與結算。
- 拒絕偽造分數、跳題、修改 UID／題號／開始時間／答案時間／獎金、重用答案、重置錦囊、重開已完成題局及重複加分。
- 拒絕匿名或其他 UID 讀取私人玩家資料；公開排行榜查詢需有上限；舊集合拒絕讀寫。

GitHub Actions 工作流程為 `.github/workflows/millionaire-rules.yml`，相關修改後會自動重新驗證。測試固定使用 `demo-hk-millionaire`，沒有接觸正式玩家資料。

## 全新進度設計

按遊戲擁有者指示，不保留舊版進度相容邏輯。只接受 `hk-2026-11-v4`，改用四個 `hkm_v4_*` 集合及 `sky.hk-millionaire.today.v4` 本機 key。新建玩家的獎金、稱號、圖鑑及歷史從零開始；原 Firebase 登入身份保留。舊文件沒有被刪除，新版不讀寫它們。

規則按操作驗證變更欄位，保持未變欄位及狀態不變；只計算一次本題所屬難度的題號與答案。移除多版本抽題表及每次操作重複整份狀態驗證，避免超過運算上限。
