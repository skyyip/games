# 玩家社群與合作公司：Spark 版

入口：「其他人生選擇」→「玩家社群與合作公司」。此版本適用 Firebase **Spark**，只使用 Authentication、Cloud Firestore 及靜態網站，不需要 Cloud Functions、Cloud Scheduler 或 Blaze。

## 玩家可以做甚麼

- Email／Google 帳戶可建立漫畫名片、固定玩家代號、介紹及最多三項自述專長。匿名帳戶先綁定登入方式，原有人生保留。
- 決定是否公開名片、顯示職業、接受邀請及同意好友推薦。不公開現金、健康、IQ／EQ／PQ／JQ、Email、人生識別或私人劇情。未公開名片仍可由已接受的好友及目前公司夥伴查看；公開公司資料包含團隊UID。
- 好友邀請需本人接受。提供三種快捷訊息、移除好友、封鎖、解除封鎖及舉報。每對玩家的訊息只保留發訊者最近一則，至少相隔60秒；已結束好友關係需等24小時才能再次邀請。
- 建立一間合作公司，負責人之外最多八位真人夥伴。這是單人職業之外的合作，不強制轉職、不收費，也不調整單人NPC或薪金。
- 刊登六類工種、合作條件、公告，邀請或接受玩家申請。公司確認條件後，候選人仍須最後接受才能加入。候選人可提出新條件；好友推薦先由候選人同意，再由公司邀請。已處理公司邀請需等24小時才能重新提出。
- 負責人發布文字委託，夥伴認領、提交處理建議，由負責人人工確認或要求補充。完成紀錄不代表專業認證、伺服器評分或排名。
- 可離職、移除成員、提出交接及結束公司。接任者必須本人接受，原負責人才退出公司；不能單方面把管理權交給其他玩家。
- 換人生或65歲退休後，下次開啟社群會同步：夥伴離職，負責人的公司暫停，等待交接或結束。好友及原有紀錄保留。已離職夥伴未完成的委託由負責人手動取消；沒有資金被鎖住或到期扣款。公司結束後，其他夥伴在下次開啟社群時解除舊職位。

## 完成委託、合作紀錄與成長

1. 負責人發布委託，另一位公司夥伴認領並提交；可退回補充，只有負責人能確認完成。
2. 新版認領的委託完成時，以同一交易建立雙方各一份私人紀錄：公司、標題、工種、交付、回饋、合作夥伴當時的公開名字／UID及確認時間。公司頁仍顯示最近30份委託；「合作紀錄」每頁20份，可逐頁查看，離職／結束公司仍保留。
3. 在社群的「合作紀錄」自行領取成長。交付者綁定認領時的人生；負責人綁定驗收時的人生。換人生不轉移獎勵；退休只回顧。

| 工種／身份 | 成長方向 |
| --- | --- |
| 製作與設備 | IQ、JQ |
| 科技與資料／研究與規劃 | IQ、JQ |
| 照顧與服務 | EQ、PQ |
| 設計與創作 | IQ、PQ |
| 溝通與行銷 | EQ、JQ |
| 負責人回饋與驗收 | EQ、JQ |

使用既有的屬性遞減成長公式，每次名義投入兩點主要屬性、一點次要屬性，實際通常只提升約0.03–0.44點；接近上限可能為零。領取後顯示實際數值並寫入人生繪本，既有每日成長回顧與65歲退休感言會包含已領經驗。沒有扣安排或即時發薪，不能替代工作證據、受督導實習或資格。

每位帳戶每日最多三份（UTC+9零時重設，由Firestore伺服器時間判定），每段人生每個遊戲月另限三份。超額可留待之後，沒有強制登入或到期懲罰。每份只可一次；領取同時更新伺服器配額，雙分頁競爭不重複扣額。雲端已確認但尚未存入人生時可重試，不再占一次額度。本機存檔保存已套用ID，重載不再次增加。

私人存檔仍是客戶端模擬，手動修改／回復舊備份不能當成防作弊排行榜。規則能驗證確認者、紀錄、人生識別及每日領取次數，不能判斷文字交付的真實品質或阻止多帳戶串通。

## 與先前 Functions 方案的差別

已移除合作點、首次點數、公司基金、報酬協商、預留款、支付、自動評分、自動退款、排程清理、自動聲望／資歷及定時後續委託。合作條件是純文字約定，不是金錢合約。

合作不增加現金、專業技能、人脈、聲望、資格、每月安排或退休資產。新版本加入有限的IQ／EQ／PQ／JQ成長，必須先由負責人確認、再由本人領取；不是伺服器自動評分，亦不把自述文字當成專業成績。舊Functions收據不能領獎，舊版已完成／已認領的委託不補發。

舊 `career365_social_*`／`career365_cards` 等 Functions 集合保持禁止客戶端存取；新資料使用 `career365_spark_*` 集合，沒有自動搬移。此專案先前尚未成功部署 Functions。儲存庫已移除 Functions 原始碼、依賴和部署設定；若曾自行另外部署過舊 Functions，需由管理員在Console另行確認停用，這次靜態更新不會替你刪除雲端資源。

## 部署：只需要 Spark

唯一專案：`sky-playground-career-365`。青蛙專案不受影響。

1. [Firebase Console](https://console.firebase.google.com/project/sky-playground-career-365/overview)：確認已建立預設Firestore，並啟用Email／Password、Google登入及網站的Authorized domains。毋須升級Blaze或啟用Functions。
2. 在自己的電腦安裝Node.js22或以上，於儲存庫根目錄執行：

```bash
npm install -g firebase-tools
firebase login
firebase projects:list
npm ci --prefix career-365
npm run social:check --prefix career-365
```

3. 檢查輸出專案為`sky-playground-career-365`，範圍只有`firestore:rules,firestore:indexes`，然後執行：

```bash
npm run social:deploy --prefix career-365
```

這個指令固定使用`career-365/firebase.json`及本遊戲設定的projectId。`firebase:deploy`亦部署同一組規則／索引。不能只部署索引：新的社交規則需要一起發布，否則操作會被拒絕。不要把社交集合改成公開讀寫，也不用執行`firebase init`覆寫設定。

4. 到[Firestore索引頁](https://console.firebase.google.com/project/sky-playground-career-365/firestore/indexes)等待三個複合索引可用：

| 集合 | 欄位 |
| --- | --- |
| `career365_spark_requests` | parties陣列包含、updatedAt降序 |
| `career365_spark_requests` | companyId升序、updatedAt降序 |
| `career365_spark_companies` | listed升序、status升序、updatedAt降序 |

5. 發布最新版靜態網站。使用兩個Email／Google帳戶驗收：名片、好友接受、公司邀請與條件協商、認領／提交／負責人確認、離職／交接、封鎖及舉報。到「合作紀錄」核對雙方紀錄並各領一次；重新整理與重載後不重複成長，金錢及專業資格不變。

## 權限、用量與管理

規則以Firebase Auth UID判斷操作者；支援已綁定Email／Google、但登入token仍標為anonymous的帳戶。直接匿名或未登入無法使用社群。玩家不能任意修改他人名片、私人人生識別、公司職位或委託狀態。

好友的兩份對稱文件、加入公司時的邀請／名額／私人職位、公司交接均以原子交易及`getAfter`規則共同驗證，不能只改其中一份。只有負責人可以確認委託，亦不能把已完成委託改回進行中。委託本身拒絕額外餘額、分數或自訂獎勵欄位。合作紀錄在`career365_spark_rewards/{uid}/receipts/{companyId_taskId}`，每日配額在同一私人路徑的`days/{dayNumber}`；紀錄內容不可更改或刪除，只能以原子交易從pending轉為granted並消耗當日配額。此版本必須先部署新版規則；沿用舊規則會拒絕新版認領／完成／領獎。沒有新增複合索引。私人雲端存檔規則維持原有版本檢查及本人權限。

社交詳細畫面與Firestore SDK延後載入；詳細列表在開啟、手動重新整理或操作後讀取。右上角通知另外在註冊帳戶登入且頁面可見時，使用兩個有上限的即時監聽，讀取最近50筆好友關係及40筆相關公司申請，沒有背景輪詢。隱藏頁面或切換帳戶立即停止監聽；返回頁面重新連線。通知僅列待處理的收到項目，查看即在目前裝置標記已讀，按專案與帳戶隔離；不會接受申請、改動人生或提供跨裝置已讀同步。匿名帳戶須先登入；錯誤保留上次內容並可重試。沿用現有規則與索引，無需新增部署。每次列表有規則與客戶端上限：公司30、委託30、公司邀請40、好友關係50、訊息30、封鎖100、私人合作紀錄每頁20；顯示的是最近紀錄，不代表全帳戶總量。封鎖即使未列在最近100筆，規則仍會阻止直接互動。公共資料同樣需要註冊帳戶，私人名片不可列舉。

Spark仍有Firestore免費配額；本版本不保證無限用量。額度耗盡時社交暫停，本機人生與離線存檔可繼續。查詢上限及每對玩家冷卻不等於伺服器級全域限流。

舉報位於`career365_spark_reports`，只允許舉報者寫入及本人單筆查看，其他客戶端不能讀取或列舉。同一對玩家24小時內只記一次；由管理員使用Console人工處理，不會自動停權。介紹、公告及交付內容均按純文字轉義顯示。

## 本機驗證

```bash
npm ci --prefix career-365
firebase emulators:exec --project demo-career365 --only firestore \
  --config career-365/firebase.json \
  "npm run test:rules --prefix career-365 && npm run test:social:rules --prefix career-365"
```

`test:rules`保留原有私人存檔及舊Functions集合拒絕測試；`test:social:rules`使用真實Firebase客戶端和實際Spark adapter，驗證名片私隱、同意、條件協商、推薦、八人名額競爭、認領競爭、手動交付、雙方私人紀錄、禁止偽造獎勵、每日限額與重試、退休／交接、封鎖／舉報及查詢上限。只連接本機8090的demo專案，不建立正式帳戶或發送正式訊息。

`scripts/social-browser.mjs`同樣需要本機Firestore模擬器，以實際Web SDK及安全規則執行四尺寸雙玩家流程；Auth是測試身份。`scripts/social-production-check.mjs`驗證打包版訪客社群畫面及安裝後離線本機遊玩，不呼叫正式Firebase。

新版名片提供四十款漫畫造型，首次依目前人生的隨機頭像預選，也可自行更換。原有八個頭像安全值不變，支援comic-8至comic-39。必須先部署最新版Firestore規則，才能發布或更新使用新增造型的名片；沒有新增公開欄位或索引。交付表提供方案／依據／限制／回應提問的提示；退回補充後保留先前內容，可修訂再提交。負責人的提問及最後回饋沿用既有驗收流程。

## 跨職業專案範本與NPC演練 — 2026-11-06

公司負責人的委託表加入三組範本：期間限定咖啡店、AI客服小試點及社區友善服務日。選擇只填標題／描述草稿，不會自動發布或指派。負責人可拆成不同工種的委託，把上份已確認成果整理到下一份描述，沿用認領、提交、覆核、取消與私人合作紀錄。未能繼續的委託仍可由認領者／負責人按原有權限取消再安排。

單機每週案例入口同時提供三段NPC合作演練；各段保存玩家交接做法，供下一位NPC角色參考。NPC內容不寫入公共公司或真人合作紀錄，不領社交屬性獎勵，也不代替真人驗收。兩者沿用現有Spark架構，無額外Firestore索引或規則部署。

## 開發、營運與資料AI合作範本 — 2026-11-06

公司範本增至六種，新增網站結帳整合（前端／後端／全端）、電商活動與社群（產品／電商／社群）、資料與AI品質覆核（資料／模型／治理）。選擇仍只填草稿，不自動發布、收費或呼叫真實工具。新的18種職業另有三段專屬NPC交接，隨私人存檔保留；這些練習不會寫入真人合作紀錄或發社交獎勵。既有真人驗收、取消、重新安排及Spark權限不變。

## 單人故事與真人合作的入口調整 — 2026-11-06

獨立NPC重複演練已從主流程移除。四條單人職場連載中的師傅／同事直接參與任務，人物支持及作品記錄屬於本機人生，不產生真人合作收據或社交屬性獎勵。每週特別委託也直接走單人職業流程，花明示的安排及工作成本。真人公司六種草稿範本、邀請、認領、提交及人工確認保持原有權限；沒有自動替真人交付或驗收，也沒有新增Firestore欄位、索引或Functions。

## 全職業人物支援 — 2026-11-06

單人故事中的固定夥伴、最多三份支持及工具／協作專精，現在適用所有405種職業，並各自保存於該職業的人生紀錄。這些單人角色不會代替真人認領、提交或驗收，也不產生真人合作收據或社交成長獎勵。真人好友、邀請及公司協作仍沿用原有Spark規則與索引，無新增部署要求。
